### Assembling the Data

(Specific filenames are given below. The actual values will come from `config.toml`.)

Using the token-morphology index `data/indexes/Aristophanes_Frogs_morphology_index.tsv`, see if there is one or more index-entries for a given token. If there is, they all will recorded and encoded in `div#textdata`. 

The CITE2-URN in the index should map to the text-specific morphology dictionary, *e.g.* `data/morphology/frogs_morph.cex`. The corresponding entry will have a human-readable description of the morphology, in Markdown, in property `desc` (the second `#`-delimited column in the `#!citedata` block) as well as a CITE2-URN to the lexicon (property `lsj`, col 7). We want both.

With the lexicon URN, we can grab the short-definition from `source-data/dictionaries/lsj_short_defs.tsv`.

If there is more than one index-entry for the token-CTS-URN, we want them all.

All that should go into the data-div for this token in some structured HTML way, keyed to the token-level CTS-URN. Like:

```
  &lt;div id="morphdata"&gt;
      &lt;div class="morph4token" data-tokenurn="urn:cts:greekLit:tlg0019.tlg009.fu.sp:2.1.text.token.3"&gt;
       &lt;div class="formparsing" data-morphurn="urn:cite2:fufolio:greekmorph.2026a:20260604T0959107277"&gt;
          &lt;!-- We would parse the following Markdown before insertion --&gt;
          **ἀεί**. From **ἀεί**. Adverb. [d--------]. See `urn:cite2:hmt:lsj.chicago_md:n1564`.
       &lt;/div&gt;
       &lt;div class="lsj_shortdef" data-lsjurn="urn:cite2:hmt:lsj.chicago_md:n1564"&gt;
        &lt;a href="{{lsj_url}}" class="shortdeflink"&gt;ἀεί; ever, always; until now; from of old; eternity; immortals; …[2 omitted]… for ever; Et.Gud.z; aevum&lt;/a&gt;
       &lt;/div&gt;
  &lt;/div&gt;
```

I have added `["outut"]["lsj_url"]` as a configuration in `config.toml`.

By default, all of the contents of `div#morphdata` will be hidden by CSS.

For now, we can simply populate `div#morphdata` as described (or if you can think of a more sound way!). 

After that, we can add functionality so that some user-interaction with a token will display the morphological-lexical data associated with that token.
